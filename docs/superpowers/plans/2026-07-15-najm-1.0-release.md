# Najm 1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the four existing Najm packages through a verified `1.0.0-rc.0` release under `next`, then promote unchanged release code to `1.0.0` under `latest`.

**Architecture:** Changesets remains the coordinated version authority. Static API-contract tests and a clean tarball-consumer harness enforce the v1 compatibility and distribution boundaries, while GitHub Actions selects `next` or `latest` from the generated semantic version. RC publication and stable promotion are separate reviewed checkpoints with registry readback after each write.

**Tech Stack:** TypeScript, `node:assert`, `tsx`, npm workspaces, Changesets 2.29, tsup, GitHub Actions, npm provenance, VitePress.

## Global Constraints

- Release exactly `@monsef-nbj/najm`, `@monsef-nbj/najm-compiler`, `@monsef-nbj/najm-router`, and `@monsef-nbj/najm-server` as one fixed version group.
- Keep the repository CLI and `create-najm-app` unpublished and explicitly deferred.
- Publish `1.0.0-rc.0` under `next`; do not move `latest` during RC hardening.
- Promote to `1.0.0` only after every evidence gate passes and no confirmed Tier 1 regression remains open.
- Any behavioral change after the verified RC requires another RC and a complete gate rerun.
- Publish only through reviewed GitHub Actions with npm provenance.
- Never attempt to republish an immutable npm version or leave the fixed package group at mixed versions.
- Node.js 20 remains the package runtime floor; release CI uses Node.js 22.
