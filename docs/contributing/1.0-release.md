# Najm 1.0 release runbook

## Local evidence

Run `npm ci`, `npm test`, `npm run typecheck`, `npm run build:packages`, `npm run test:packages`, `npm run bench`, `npm run docs:check`, and `git diff --check` from a clean checkout.

Inspect `npm pack --json --workspaces --dry-run`. All four versions and export maps must agree, no package may advertise a CLI `bin`, and only declared distribution files may ship.

## Release candidate

Changesets must be in `rc` prerelease mode. Merge the reviewed version PR and let GitHub Actions run `npm run release:ci`; RC versions select `next`. Read back each package with `npm view <package>@1.0.0-rc.1 version dist-tags --json`, inspect npm provenance, and install all four `@next` packages into a clean external project.

Search open GitHub issues for confirmed Tier 1 regressions and record the exact query. Stable promotion is blocked while any confirmed regression remains open.

## Partial publication recovery

Stop automation and inspect all four immutable registry versions. Never bump only part of the fixed group and never retry an already published version. Publish only missing packages at the same coordinated version, rerun registry consumer verification, and move no stable tag until all four artifacts pass. Correct a mistaken dist-tag only after registry readback.

## Stable promotion

Confirm no behavior commit follows the verified RC tag. Exit prerelease mode, generate versions, and rerun the complete evidence gate. Stable `1.0.0` uses untagged publication to `latest`. Verify registry consumers and provenance before creating `v1.0.0`, announcing general availability, or deploying stable installation copy.

## Rollback limits

npm versions are immutable. Deprecate a defective version and publish a corrected version; do not attempt replacement. Restore dist-tags only to a previously verified version. Document the incident and migration path.

The standalone CLI and `create-najm-app` remain deferred and repository-only throughout the 1.0 release.
