# Najm 1.0 clean-room adoption report

## Scope

The adoption project was created outside the repository at `C:/Users/nouba/projects/najm-v1-adopter/`. It uses npm packages or packed registry-shaped artifacts only, Node.js 26.3.1, npm, Vite 6, and the public package exports. No workspace alias, repository CLI, or source import is used.

## Journey

The application covers a signal-backed event, a reusable component, `client:load`, `client:visible`, a dynamic `[id]` route, root layout, redirect middleware, store/context calls, an SSR error boundary, production build, production preview, development serving, and browser hydration.

## Findings

### RC channel tag unavailable

- Command: `npm install @monsef-nbj/najm@next @monsef-nbj/najm-compiler@next @monsef-nbj/najm-router@next @monsef-nbj/najm-server@next vite`
- Result: `ETARGET No matching version found for @monsef-nbj/najm-compiler@next`.
- Classification: release-channel defect.
- Resolution: `scripts/release-tag.ts` now publishes the RC atomically under `next` through Changesets and npm trusted publishing. Explicit `1.0.0-rc.0` versions were used to continue diagnosis.

### Published server resolved its own package directory

- Command: `npm run build` using `@monsef-nbj/najm-server@1.0.0-rc.0`.
- Result: zero routes followed by `Failed to load url /runtime/index.ts`.
- Classification: package/distribution defect.
- Resolution: build and development roots now use the adopter working directory; runtime resolution uses the published `@monsef-nbj/najm/core` export. The packed consumer gate executes a real build.

### Getting Started component omitted template wrapper

- Documentation step: create `src/pages/index.najm` from Getting Started.
- Result: `a .najm file needs a <template> block`.
- Classification: documentation error.
- Resolution: the example now wraps markup in `<template>`, enforced by `tests/test-docs-content.ts`.

### Compiler plugin ran twice

- Setup: documented `vite.config.ts` plus the published server build command.
- Result: generated JavaScript was passed through the `.najm` compiler a second time and rejected for lacking `<template>`.
- Classification: framework integration defect.
- Resolution: server tools inspect loaded Vite configuration and inject `vite-plugin-najm` only when the application has not configured it. The packed consumer reproduces the documented Vite setup.

### Preview resolved package-local dist

- Command: `npm run preview`.
- Result: `ENOENT ... node_modules/@monsef-nbj/najm-server/dist/manifest.json`.
- Classification: package/distribution defect.
- Resolution: preview serves `dist/` under the adopter working directory; the source contract is regression tested.

### Advanced guides lack executable signatures

The routing, store/context, and boundary guides explain concepts but do not show complete layout, middleware, `defineStore`, or `withErrorBoundary` examples. A Pinia-shaped `defineStore(name, definition)` assumption failed with `def.state is not a function`; the actual public signature is `defineStore(definition)` and actions receive state explicitly under `$actions`.

- Classification: documentation gap.
- Residual action: add complete copy-paste examples to the advanced guides before stable promotion.
